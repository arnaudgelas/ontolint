# Changelog

All notable changes to ontolint, generated by `scripts/bump_version.py`.

## [0.13.0] - 2026-11-12

No output holds a credential from an IRI's userinfo any more, one ontology IRI declared by several
documents of a run is reported (ONT007, ONT008), label, definition and note predicates are closed
over sub-properties and equivalents, and the SHQ rules follow the SHACL and XSD specifications and
no longer merge blank shapes.

### Upgrade notes

Results change; regenerate your baseline once with `--write-baseline` and review your `--fail-on`
results after upgrading.

- **Every IRI userinfo is masked in every output**, user name included: `https://alice:pw@h/x` is
  now `https://****@h/x` in every finding's focus, message, evidence and subject, in the report and
  on stderr. Findings about such IRIs, and blank nodes whose content holds one, change identity, so
  their baseline entries stop matching. Rotate any credential an older report or baseline printed.
  SEC014 also finds passwords 0.12.0 missed (`https://u@x:pw@h`, `https:/u:pw@h`, `https:u:pw@h`,
  an IRI nested in a query), and a parser error about such a file keeps its line number but no
  excerpt.
- **ONT007 is a new default-on warning** (an ontology or version IRI declared by documents whose
  content differs, among the inputs, one import closure, the `--import-dir` candidates or the graphs
  of a dataset), so such runs exit 1 under `--fail-on warning` and the ci, obo, fair and strict
  profiles; **ONT008** (identical copies) is info. An ODK edit file next to its release is not
  reported. `--ignore ONT007,ONT008` restores the 0.12.0 result. The SARIF `ruleIndex` of every rule
  after ONT006 shifts by 2.
- **SHQ findings on blank shapes are no longer merged**: each blank shape gets its own
  `_:<12 hex digits>` focus computed in the shapes graph, instead of the shared `_:0e072f628a4c`,
  so runs report more findings and those baseline entries (version 1 and 2) go stale.
- **SHQ rules follow SHACL and XSD**: SHQ003, SHQ010, SHQ011 and SHQ023 report findings they did not
  before, and SHQ001, SHQ002, SHQ003, SHQ006, SHQ011, SHQ021 and SHQ024 drop some. Version 2
  baseline entries keep matching the findings that remain.
- **Label, definition and note predicates are closed over `rdfs:subPropertyOf` and
  `owl:equivalentProperty`**: a term labelled, defined or noted under a vocabulary's own
  sub-property or equivalent is now read as such. LEX001, LEX002, LEX008, SKOS004, CLS015 and ONT006
  findings can disappear, and the LEX rules that judge label or definition text can report on the
  values newly read. The counts in METRIC001, METRIC002, METRIC003, METRIC009 and METRIC012 messages
  move, so version 1 entries for them stop matching.
- **OWL011, OWL022 and OWL040 read one datatype list**: OWL011 no longer reports an `owl:allValuesFrom`
  filler of `rdfs:Literal`, `rdf:langString`, `rdf:PlainLiteral`, `rdf:XMLLiteral`, `rdf:HTML`,
  `rdf:JSON`, `owl:real` or `owl:rational`, while OWL022 and OWL040, both errors, now report
  `rdf:JSON` on an object property and can fail a run under the default `--fail-on error`.

## [0.11.0] - 2026-11-11

Baselines no longer depend on message wording, findings say which named graph of a dataset they come
from and carry SHACL's own evidence, SHACL validation can be bounded in time, and a long list of
rules count, word and decide what their specifications say.

### Upgrade notes

Results, messages and some options change; review a baseline and your configuration after upgrading.

- **Regenerate your baseline once** with `--write-baseline`. A baseline now also records a
  message-independent identity per finding (rule, focus and subject), so later message fixes no
  longer reopen accepted findings, and a baseline written for one file carries over to a
  multi-file run and back. A baseline written by 0.10.x keeps working, but these messages and foci
  changed, so its entries for them stop matching once (a finding that disappeared goes stale, which
  fails `--fail-on-stale-baseline`): OWL013 (a literal with a line break), OWL032, OWL034, OWL036,
  OWL040 and OWL042 to OWL045 (a literal prints in N3, not as a Python repr), SEC005 and SEC012 (one
  finding per subject and predicate), SEC014 (its focus), and the METRIC findings below. Rotate any credential that a committed SEC014 report or
  baseline exposed: older fingerprints hashed the unmasked IRI.
- **Options and configuration that were silently ignored are now refused, with exit 2.**
  `--select` or `--ignore` naming SEC001, SEC002, SEC003, SEC006, SEC009, SEC010, SEC011, SEC013,
  SEC015, INPUT001 or TOOL001 (or the INPUT or TOOL family) fails with TOOL001; a policy file whose
  `ignored_rules` or `severity_overrides` names one of them fails with GOV020; a policy whose
  `metric_min_property_class_ratio` exceeds `metric_max_property_class_ratio` fails with TOOL001.
  None of them had any effect before: remove them. An unwritable `--output` is TOOL001 and exit 2,
  where it was a traceback and exit 1.
- **New findings, which can make a run fail.** OWL010 (empty and malformed property chains), OWL019
  (non-simple properties through sub-properties, equivalents, inverses and symmetry, and in
  cardinalities, `owl:hasSelf` and disjointness), OWL032 and OWL033 (`owl:disjointUnionOf`), OWL034
  to OWL037 (several properties, constraints or fillers, and a qualified minimum above an
  unqualified maximum), SHQ008 (derived integer types such as `xsd:nonNegativeInteger`), SHQ011
  (a `\/` escape and patterns Python accepts but XPath rejects), ALIGN003 (`skos:relatedMatch` in an
  exactMatch chain) and SKOS009 (the mapping sub-properties). LEX002 follows `rdfs:subPropertyOf`
  transitively and counts sub-properties of `extra_definition_predicates`, so a definition through
  `ex:def2 ⊑ ex:def1 ⊑ skos:definition` is no longer reported missing, and METRIC002 changes with it.
  The named graphs of a JSON-LD file are linted, as TriG and N-Quads graphs have been since 0.10.2.
  A seven-repository run found none of these except the METRIC changes below, so what they report on
  your ontologies is not known from it.
- **METRIC counts and wording changed.** METRIC001 counts exactly the classes LEX001 reports (an
  IRI-valued label is not a label; deprecated classes count as labelled); METRIC005 exactly those
  CLS001 reports; METRIC008 the properties OWL005 and OWL006 both report; METRIC006 and METRIC007
  count relation properties only, so annotation properties no longer count; METRIC010 ignores
  references between namespaces the ontology owns (its header IRI or `--base`); METRIC013 treats
  SHACL shapes and reification as structure. A finding whose value rounds to its limit now shows
  more digits (`0.303 > 0.300`, not `0.30 > 0.30`). Counts fall and findings can disappear;
  METRIC006 can newly fire. Thresholds, rationale and overrides are in `docs/metric-thresholds.md`.
- **Reports.** JSON and SARIF findings gain `graphs` (a dataset's named graphs; absent for a file
  with only a default graph, whose output is unchanged) and, for SHACL001, `evidence` (the
  result path, value, constraint component and severity of the SHACL result). Text output is
  unchanged. `max_validation_seconds` (policy key and flag) bounds SHACL validation; SHACL now runs
  with the network disabled, as parsing does.
- `--import-dir` now warns when it skips a file the safe loader refuses.

## [0.10.2] - 2026-11-10

Four ways a run could pass, or fail, without the ontology deserving it: SHACL results lost with an
ontology background, imported shape libraries never applied, named graphs never read, and ROBOT's
own failures reported as profile violations.

### Upgrade notes

Results change; review a baseline after upgrading.

- New findings, which can make a run fail: with `--follow-imports`, SHACL now reports results on
  nodes the data mentions only as objects (`sh:targetObjectsOf`), and validates the shapes of every
  shape library the shapes file imports (a `TOOL009` note names each); the named graphs of a TriG
  or N-Quads file are linted with its default graph, where they were ignored.
- `SEM001` is reported only when ROBOT lists profile violations. A missing image, a Docker, Java or
  permission error is now a failed rule (exit `2`, with ROBOT's output in the rule's detail),
  where it was a `SEM001` finding (exit `1`). Its focus is `(ontology)`, not the file's absolute
  path, so baseline entries for `SEM001` findings must be regenerated.

## [0.10.0] - 2026-11-10

Multi-file layouts that `owl:imports` does not describe: findings can be grouped by the modules
inside one file (by annotation or by namespace), SHACL shapes can be taken from the validator a
W3C PROF profile names, and a pattern library's index is checked against its pattern ontologies
(`LIB001`-`LIB003`). Each was validated on the public ontology that shows the layout.

### Upgrade notes

Two messages changed, so baseline entries for their findings no longer match: regenerate the
baseline with `--write-baseline` after upgrading.

- `ONT005` names the provenance that is missing: "Missing creator and dcterms:created
  provenance.", "Missing creator provenance." or "Missing dcterms:created provenance.", where it
  always said "Missing creator or dcterms:created provenance.".
- `OWL013` prints the literal in N3 (`"text"@en`, `"1"^^<http://www.w3.org/2001/XMLSchema#integer>`)
  instead of its Python repr (`rdflib.term.Literal('text', lang='en')`).

Nothing else changes by default. The new options leave findings and fingerprints alone, and the
`LIB` rules are `skipped` unless `--pattern-library` is given; JSON and SARIF gain keys only when
module grouping is on.

## [0.9.0] - 2026-11-09

Specified rules and OWL syntaxes: every error-severity rule and the whole OWL family now state
their scope, conditions and exclusions, which fixed defects in fifteen of them. ODK edit
files and other OWL Functional, Manchester and OWL/XML files lint directly with
`--convert-with-robot`, and SEM001 reports grouped violations instead of ROBOT's raw output.

### Upgrade notes

Default output changes; review a baseline after upgrading.

- Fewer findings, so some baseline entries become stale (nothing new fails): terms of well-known
  vocabularies (Dublin Core, SKOS, DCAT, IAO…) that the ontology declares only to use them no
  longer draw `LEX001`, `LEX002`, `METRIC003`, `IRI005` or `IRI008`; `OWL011` accepts a universal
  restriction closed by a sibling existential, `hasValue`, `hasSelf` or minimum (the closure
  axiom it recommends); `OWL024` accepts `owl:bottomObjectProperty` and
  `owl:bottomDataProperty`; `OWL036` to `OWL039` read a cardinality of `"-0"` as 0; `SKOS001` and
  `SKOS002` treat `"a"` and `"a"^^xsd:string` as one label, `SKOS001` compares language tags
  case-insensitively, and `SKOS002` skips IRIs the linted file does not own; `SHQ011` and
  `SHQ018` follow XPath (regex flags `x` and `q`, numeric type promotion).
- New findings, which can make a run fail: `OWL008` also reports a symmetric property that is the
  object of `owl:inverseOf`; `OWL022` knows `owl:real`, `owl:rational` and `rdf:PlainLiteral`;
  `SKOS002` also checks resources with only alternative or hidden labels; `SKOS008` checks
  `skos:OrderedCollection`; `SKOS009` follows `skos:broaderTransitive`, so a concept related to
  its grandparent is reported; `SKOS016` also checks `skos:semanticRelation` and
  `skos:mappingRelation`.
- `SEM001` messages over a profile report now count and group the violations ("7 violations: Use
  of undeclared annotation property: …#definition (6), …"), so their fingerprints change. The full
  report moves to a new optional `details` field (JSON `details`, SARIF `properties.details`);
  `schema_version` stays 1.
- The safe loader is stricter: a path through a symlinked directory is refused (`SEC009`),
  catalogs are bounded by `max_input_bytes` (`SEC001`), and the network guard also covers
  `gethostbyname`, `gethostbyaddr` and `sendto` (`SEC013`).
- OWL Functional, Manchester and OWL/XML inputs still fail by default, with an `INPUT001` message
  that now names `--convert-with-robot`. That option needs Docker and the ROBOT image (see the
  README). Turtle that starts with an anonymous blank node (`[] a ex:K .`) parses again; 0.8.0
  read it as JSON-LD.
- On Linux the ROBOT container (`--owl-profile`) runs as the calling user, so it can write its
  report; with 0.8.0 a profile run under a standard Docker install failed with `SEM001` "Permission
  denied".

## [0.8.0] - 2026-11-09

Real-world ontologies: fixes and new checks from linting fifteen public ontologies. ontolint now
judges only an ontology's own terms, handles the Protégé and ODK multi-file layouts, reads Turtle
saved as `.owl`, and gains four rules.

### Upgrade notes

Default output changes; review a baseline after upgrading.

- Terms an ontology only merges in or references (BFO, OBO, DC, schema.org…) are no longer judged
  when the ontology IRI owns none of the declared terms: the dominant namespace decides instead of
  "own everything". Baseline entries for those terms become stale; nothing new fails.
- New rules, on by default: `DATA003` (ill-typed literal, including values typed `rdfs:Literal`),
  `DATA004` (datatype outside the OWL 2 datatype map, such as `xsd:anyType` or `xsd:date` ranges)
  and `IRI018` (Protégé placeholder ontology IRI) are warnings, so a run with `--fail-on warning`
  can start failing; `IRI019` (declared prefix no IRI uses) is info.
- Relative `owl:imports` are one `GOV002` note instead of `SEC008` findings holding a local path.
- Messages, and so baseline fingerprints, change for `OWL011` and `OWL043` findings that were on a
  blank node (they now name the term), for `ALIGN015`, and for `ONT003` when the file names its
  licence only in an SPDX comment. `METRIC005` no longer counts classes under an external
  superclass, and `LEX002` and the header rules report fewer false positives.
- With `--follow-imports`, the import root defaults to the enclosing repository, each module's own
  catalog is read, and a catalog entry naming a missing file leaves the import unresolved with a
  `TOOL004` note instead of failing the run.

## [0.7.0] - 2026-11-09

Modular ontologies, continued: with `--follow-imports`, findings point at the module that declares
their term, the closure is judged as the root's one published ontology, and SHACL validates
instance data against the ontology its shapes import.

### Upgrade notes

Runs without `--follow-imports` or `--catalog` are unchanged. With them:

- JSON findings carry the declaring module's `path`, SARIF results that module's
  `artifactLocation` and region, and text findings an `In:` line, instead of naming the root file.
  Baseline fingerprints are unchanged.
- Header rules (`ONT003`-`ONT006`, `GOV004` and the like) judge only the root ontology; imported
  modules inherit its metadata. Owned terms derive from the root IRI, so a vendored vocabulary with
  its own namespace is no longer judged. `METRIC011` ignores imports that resolved to local modules.
- With `--shapes`, a shapes file that `owl:imports` the ontology supplies it as background for
  SHACL. Valid data that used to report false violations now conforms, and data that reached a
  target class only through a subclass is now validated, so some runs gain real violations.
