# Changelog

All notable changes to ontolint, generated by `scripts/bump_version.py`.

## [0.6.0] - 2026-11-08

Modular ontologies: `--follow-imports` (or `--catalog FILE`) lints the `owl:imports` closure of an
umbrella ontology from local files, through the `catalog-v001.xml` next to it. See "Modular
ontologies" in the README.

### Upgrade notes

- Default runs are unchanged: imports are followed only with `--follow-imports` or `--catalog`.
- New rule `SEC015` (import closure exceeds its limits) and policy keys `max_import_depth`
  (default 16) and `max_imported_files` (default 100). The catalogue now has 295 entries.
- `SEC007`'s suggestion text changed to point at `--follow-imports`. Baselines are unaffected:
  fingerprints hash the message, not the suggestion.

### Added

- follow owl:imports offline through an OASIS XML catalog (0e5a2aa)

### Documentation

- record modular stage 1 in TODO.md (c20b339)

## [0.5.1] - 2026-11-08

### Upgrade notes

- `SHACL001` findings now carry the SHACL result severity. Data whose only results are
  `sh:Warning` or `sh:Info` no longer fails the default `--fail-on error`; use
  `--fail-on warning` to keep failing on them.
- `SHACL001` messages name blank-node shapes and focus nodes by a stable identity instead of a
  parser label. Baseline entries written before 0.5.1 for such findings will not match: write the
  baseline again (`--write-baseline`) once after upgrading. The old entries are listed as stale.

### Fixed

- keep SHACL result severity and name blank shapes stably (4456103)
- check DATA001 ranges by value, not by datatype name (4178a32)
- do not lint a SHACL prefix declaration as an ontology (0a62b70)

## [0.5.0] - 2026-11-08

### Upgrade notes

- A policy file whose `ignored_rules` or `severity_overrides` names a rule that does not exist now
  fails the run with `GOV020` and exit code 2 instead of being ignored. Fix the identifiers it
  names (`--list-rules` shows the valid ones).
- OWL044 no longer reports a direct `owl:sameAs`/`owl:differentFrom` conflict or an individual
  different from itself; OWL026 already reports those. A baseline that recorded them under OWL044
  will now list those entries as stale.
- With `--baseline`, the JSON report gains a `baseline.stale_fingerprints` key.

### Added

- reject unknown rule IDs in the policy file (OPS009) (1bd3049)
- report stale baseline entries (OPS003) (4e6b08f)
- make the CLS011 subclass threshold configurable (b402783)

### Fixed
