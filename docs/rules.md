# Rule reference

This file and the pages under `docs/rules/` are generated by `tests/rule_docs_generator.py`; do not
edit them by hand. Regenerate them with `uv run python tests/rule_docs_generator.py`.

This index lists every catalogue rule by family. Each family has its own page,
`docs/rules/<family>.md`, linked below. A page opens with the notes of the modules that implement its
rules: each module's docstring, which defines what its rules' specifications share. Each implemented
rule then lists its severity, scope, category, module and fix; its specification, quoted from the
module's docstring, or a line saying that none is written yet; and every case of `tests/rule_cases/`,
in order: each flagged case, with the first message the linter reports for it, then each clean case.
A case shows its Turtle (or says that its graph is built programmatically, is the empty graph, or is
run through the command line or an adapter), its shapes graph and its linter options. Rules that
are not yet implemented are marked **TODO** with the backend they are waiting for; they cannot be
selected and never run (see `--list-rules`). The intended behaviour of a TODO rule is a draft from
`tests/planned_rule_intents.py`, not a final specification.

Rules marked **Selectable: no** are pipeline rules, of backend `cli`
(safe-loader refusals and front-end diagnostics, never findings). They are implemented and always apply, so `--select` and `--ignore` reject them,
and `--list-rules --format json` reports them with `"selectable": false`.
