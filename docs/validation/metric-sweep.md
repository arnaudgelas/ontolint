# METRIC limit sweep

How many of the 21 pinned corpus files each `METRIC001`-`METRIC013` rule flags as its limit moves
(issue #8). It is generated by `scripts/metric_sweep.py` from the recorded measurements in
[`metric-corpus-results.json`](metric-corpus-results.json) and needs no label, no network and no
ontology body. **It changes no default.**

**What it measures:** the number of files flagged at each limit, exactly (fractions, strict
comparison as the rule makes it). A rule's value on a file changes the flag only when a limit crosses
it, so one row is given per observed value, plus the shipped default (marked); a row whose count
equals the previous row's is omitted. A rule fires strictly above its limit, except METRIC006,
METRIC009 and METRIC012, which fire strictly below it. A file below the rule's sample gate, or with no
population, makes no comparison and is never flagged.

**What it does not measure:** whether a flag is right. A flagged file is not a false positive and an
unflagged one is not a false negative until the maintainer's labels say so; for those counts, fill the
label sheet and run the calculator (`scripts/metric_sweep.py labels-sheet`, then `calibrate --labels`;
[`../metric-calibration.md`](../metric-calibration.md), "Approving the labels"). The measurements are
those of the version recorded in the results file and go stale when a rule changes; `scripts/metric_corpus.py check` says so at every release (issue #169).
